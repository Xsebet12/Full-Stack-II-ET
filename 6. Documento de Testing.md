# Documento de Testing

**Objetivo**
- Establecer cómo se ejecutan y mantienen los tests del proyecto.
- Describir el enfoque de pruebas unitarias y de MVC en el backend.

**Cómo Ejecutar**
- Windows: `./mvnw.cmd -DskipITs -DfailIfNoTests=false test`
- Linux/macOS: `./mvnw -DskipITs -DfailIfNoTests=false test`
- Ejecuta únicamente tests unitarios y de `@WebMvcTest` del backend. El frontend no tiene pruebas en este repositorio.

**Frameworks y Herramientas**
- `JUnit 5` para pruebas unitarias.
- `Mockito` para mocks de dependencias.
- `Spring Boot Test` para `@WebMvcTest` y `MockMvc`.

**Tipos de Pruebas**
- Servicios: validación de lógica, excepciones y flujos (`service.impl/*Test`).
- Controladores: endpoints con `MockMvc`, sin filtros de seguridad reales (`controller/*WebMvcTest`).
- Seguridad JWT: generación y validación de tokens (`security/JwtTokenProviderTest`).

**Patrones Clave**
- Deshabilitar filtros en `@WebMvcTest`: usar `@AutoConfigureMockMvc(addFilters = false)`.
- Mockear dependencias de seguridad cuando el contexto las requiere:
  - `ProveedorTokenJwt` y `ServicioDetallesUsuario` como `@MockBean` en pruebas de MVC simples.
  - Ejemplo: `src/test/java/com/SebastianCornejo/Proyecto/Fullstack/controller/ControladorContactoTest.java:28-39`.
- Uso de `@WithMockUser` cuando se evalúan reglas de método (roles/permisos).

**Cobertura Actual (resumen)**
- Controladores: autenticación, carrito, productos, categorías, regiones, comunas, proveedores.
- Servicios: productos, categorías, regiones, comunas, carrito.
- Seguridad: proveedor de tokens JWT.

**Buenas Prácticas**
- Mantener `@WebMvcTest` aislado del stack completo; importar o mockear solo lo necesario.
- Validar mensajes y tipos de excepciones en servicios (`RecursoNoEncontradoException`, `PeticionInvalidaException`).
- Evitar dependencias a datos reales; utilizar builders y `Mockito.when`.

**Solución de Problemas Comunes**
- Error de `ApplicationContext` por beans de seguridad ausentes: añadir `@MockBean` de `ProveedorTokenJwt` y `ServicioDetallesUsuario` en el test.
- Roles inconsistentes: al simular usuarios, usar el rol correcto en cada test (`@WithMockUser(roles = {"CLIENTE"})` o el requerido por la regla de método).
- Directorio `uploads/images`: las pruebas de subida de imágenes no escriben binarios reales; se valida flujo y respuesta.

**Comandos Útiles**
- Ejecutar un solo test: `./mvnw.cmd -Dtest=CartServiceImplTest test`
- Ver logs detallados: `./mvnw.cmd -X test`

**Estado Actual**
- Todos los tests del backend se ejecutan exitosamente: `Tests run: 92, Failures: 0, Errors: 0`.
