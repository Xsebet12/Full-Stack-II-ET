# Seed de base de datos: Tienda de productos congelados (Oracle)

Este directorio contiene un script SQL (`seed_congelados.sql`) con el esquema relacional y datos de ejemplo para un entorno de desarrollo de una tienda virtual de productos congelados enfocada en Chile.

Incluye:
- DDL para tablas: `region`, `comuna`, `categorias`, `providers`, `provider_contacts`, `productos`, `imagenes_producto`, `usuarios`.
- Poblamiento inicial:
  - 2 regiones y 4 comunas (Metropolitana y Valparaíso).
  - 6 categorías.
  - 3 proveedores con contactos.
  - 16 productos (distribuidos en distintas categorías y con stocks realistas; algunos bajo 5 para probar alertas).
  - 1 usuario administrador por defecto (`admin@tienda.cl`).

> Importante sobre contraseñas: la columna `usuarios.contrasena` debe contener un hash BCrypt. El script trae un hash de ejemplo para desarrollo. Reemplázalo por un hash generado para tu clave real (p.ej. `Admin123!`) antes de ir a producción.

## Cómo ejecutar el seed (SQLcl / SQL Developer)

1. Asegúrate de tener conexión a Oracle (puede ser vía wallet). Con SQLcl:
   ```sql
   -- Conéctate (ajusta el alias/usuario/clave)
   CONNECT usuario/clave@ALIAS_TNS
   -- Ejecuta el script
   @src/main/resources/db/seed/seed_congelados.sql
   ```

   En SQL Developer: abre el archivo y ejecútalo conectado al esquema deseado.

2. Si las tablas ya existen, puedes descomentar los `DROP TABLE ... CASCADE CONSTRAINTS;` al inicio del archivo.

## Personalización

- Cambiar el hash BCrypt del admin:
  - Genera un hash BCrypt (por ejemplo, con Spring Boot/Java usando `BCryptPasswordEncoder`).
  - Reemplaza el valor de `contrasena` en el `INSERT INTO usuarios`.

- Ajustar el umbral de stock bajo en la app:
  - El frontend ya permite setear el umbral en la vista de productos (switch "Sólo stock bajo").

## Notas de mapeo JPA ↔ SQL

- Nombres de tablas: definidos por `@Table` (p.ej. `Producto` → `productos`).
- Nombres de columnas: se usan los de la entidad o la estrategia snake_case por defecto de Spring.
- Enums (`Role`, `EstadoProveedor`) se persisten como `VARCHAR2`.
- Booleanos (`habilitado`, `principal`) se modelan como `NUMBER(1)` con `CHECK` (0/1).
- Identidades: se usan columnas `GENERATED BY DEFAULT AS IDENTITY` (Oracle 12c+).
